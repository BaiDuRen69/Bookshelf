## 4. 前置条件链（每一步的判据与执行人）

规格给的链是「用户授权 commit → 干净树 → 抬号重打 → 台账新行 → 合并」。**这条链有一处顺序陷阱**：
抬号（改 `app/build.gradle` 的 versionCode / versionName）本身就是源码改动，
如果先抬号再求干净树，树又不干净了，`pack.ps1` 照样拒绝写行。正确的展开是：

| # | 步骤 | 谁做 | 判据 / 命令 | 为什么不能跳 |
|---|---|---|---|---|
| 0 | **用户授权 commit**（并决定 A / B 选项，见 `docs/版本归属-5.9.5.md` 第 7 节） | 用户 | 明确答复 | 本轮硬约束禁止 commit；没有授权后面全做不了 |
| 1 | 按轮次分开提交 34 项 | 助手（授权后） | `git add -p` 挑 `DbRepair.java` 的块：卡 8 的 `rollbackFiles` 与 EP-I1 的 `usableList` 必须分属两个提交；`SettingsBackup.java` 同理（卡 7 / 卡 8） | 混提交会让「一行 = 一个包 = 一个提交」再次失效，也会让台账无法归因 |
| 2 | 抬号 **5.9.6 / 140** 并**单独提交** | 助手（授权后） | 台账 `:53-54` 早已写明这个方向；`app/build.gradle:13-14` | 同号覆盖发布是 I1 的根因；抬号必须自己成一个提交，否则干净树永远达不到 |
| 3 | **干净树** | 机器判 | `git status --porcelain` 为空（`tmp/` 已忽略） | `pack.ps1` 工作区不干净只打印原因、不写行（台账 `:26-28`） |
| 4 | 合并前跑一次 JVM 全量 | 助手 | `JAVA_HOME="D:/tools/jdk-21.0.2" sh ./gradlew --offline testDebugUnitTest`，当前 **630 条**应 0 失败；`MigrationSmokeTest` 5 条覆盖 v24→v26 | 合并会让 main 用户首次跨两级迁移，这是窗口里唯一真风险 |
| 5 | 抬号后重打 + 写台账新行 | 机器 | `powershell -NoProfile -ExecutionPolicy Bypass -File Bookshelf/scripts/pack.ps1` → `dist/XiaoShuFang-v5.9.6.apk`，新行 HEAD 与 SHA 一一绑定 | 不重打就没有「一份产物一个版本号」，I1 原样复制 |

| 7 | 正式槽位装机 + 回填两个人工列 | 用户装机，助手只读核 | `adb shell dumpsys package com.bai.bookshelf` 取 versionName；androidTest 若跑在 devtest/debug 上必须写明 | 本轮实测正式槽仍是 136 / 5.9.0；不回填就还是「待填」 |
| 8 | **合并到 main** | 用户确认后执行 | 合并提交本身**也要在台账新增一行**（card11 README 第 4 节 ③） | 不写行则「SHA 对不上」第三次复制 |

补充事实（降低合并阻力，不是前置条件）：

- `ci.yml` **没有 `branches:` 过滤**，只有 `paths-ignore: docs/** / **.md`。合并后 push main 会跑同一个
  workflow，不需要改 CI 配置。「CI 只在 `ui/statistics` 绿过」是历史运行事实，不是配置约束。
- **不许 squash / rebase**：台账里 5.9.5 那行已经 SHA 对不上，重写历史会让整张台账彻底失效。
- 合并只搬**已提交**的历史。34 项不 commit 就永远进不了 main——这就是「不能提交 → 不能进台账 → 不能合并」
  的闭环，唯一的钥匙是第 0 步的用户授权。
