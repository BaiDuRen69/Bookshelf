### 主界面（MainActivity + 自定义底部导航，3 个 Tab）

底部导航是**自绘 LinearLayout**（tab_shelf/tab_stats/tab_mine，图标 20dp + 间距 2dp + 10sp 文字），不要换回 BottomNavigationView——曾因固定高度裁切内部布局连续返工三轮，最终结论是自定义最稳。

### 书架 ShelfFragment（最重的页面）

- 搜索（书名/作者/出版社/ISBN/标签/分类关键词实时过滤）
- 三行紧凑筛选：分类/标签/状态/阅读 + 地点/来源/国家 + 排序/倒序/视图（v2.1 重排：常用内容属性筛选上移，排序与倒序/视图控制同处一行）
- HighlightAdapter：下拉弹层选中项高亮（加粗+主题色+浅底），闭合态 12sp 小样式
- **v3.2 加载性能优化**（用户反馈「打开 App 时书架数据加载较慢」），五条措施：
  1. **按需刷新**：`onResume` 不再无条件全量重载。先用 `BookDao.getContentFingerprint()`（一条只做聚合、不返回行的 SQL）比对指纹，一致则整页不动；不一致才走完整 `loadData`。切 Tab 回书架页因此接近零开销。
  2. **指纹兜底**：纯文本字段（书名/作者/标签）编辑不改变任何参与指纹的数值，故「录入/编辑/详情」三类页面统一走 `launchAndRefresh()`——`ActivityResultLauncher` 收到 `RESULT_OK` 时强制标脏刷新；批量删除后也直接调 `loadData()`（内部同步刷新指纹）。
  3. **并行查询**：`loadData` 原本 4 次查询在单线程池里**串行**，现用临时 7 线程池并行，总耗时取最慢那个；每个查询独立 try/catch，字典类失败降级为空、仅藏书查询失败才提示。
  4. **去重下放 SQL**：国家/来源渠道原本在 Java 里用 `List.contains()` 循环去重（O(n²)），改为 `getDistinctCountries()` / `getDistinctChannels()`。**注意 DISTINCT 必须作用在 TRIM 结果上**，写法要用子查询（见「已知坑」）。
  5. **减少无效渲染**：6 个筛选 Spinner 改为「内容变化才重建」（`fillSpinnerIfChanged` + 5 个 cache 字段），避免每次回页面都 setAdapter 全量 notify 并重置选中；三个适配器**只提交当前视图那一个**（RecyclerView 一次只挂一个，另两个的渲染纯属浪费，封面视图下还会重跑整屏 Glide）；`applyViewMode()` 末尾补 `applyFilters()`，保证换视图后新适配器有数据；两个适配器启用 `setHasStableIds(true)` + `getItemId` 返回 `book.id`，让 RecycledViewPool 能复用 ViewHolder。首次加载新增 `ll_loading` 指示（仅首次显示，后续按需刷新不闪）。
  - 回归脚本：`tools/verify_shelf_sql.py`（内存 SQLite 复现三条新 SQL，验证去重语义与指纹的 9 类变更感知/复位能力）。
- **v3.3 修复：分类/标签/地点/来源/国家下拉全空白**（用户反馈「书架页面的分类不能显示和选择了」）。这是 v3.2 优化 5 引入的回归——`fillSpinnerIfChanged` 的 cache 是 **Fragment 实例级字段、跨视图重建存活**，而 Spinner 是 `onCreateView` 里**每次全新创建**的；视图重建后新 Spinner 的 adapter 为 null，但 cache 里旧内容还在，「内容没变」的判断成立 → 跳过填充 → 永久空白（只有布局里写死 `android:entries` 的藏书状态/阅读状态/排序三个下拉正常）。修复三处：
  1. `onCreateView` 开头先 `saveSelections()` 保存用户当前选中，再复位 `spinnerReady = false; spinnersFilled = false; clearSpinnerCaches();`
  2. `fillSpinnerIfChanged` 增加 `spinner.getAdapter() == null` 的**强制填充分支**（新视图必填），并把跳过条件收紧为 `spinnersFilled && names.equals(cache)`（本视图内已填过才允许跳过）
  3. 新增 `spinnerSelectionCache`（以 cache 列表对象为 key）记忆用户选中的筛选项，填充后 `restoreSelection()` 恢复；用户主动选回首项「不限」时 `recordSelection()` / `rememberSelection()` 会清掉记忆，避免下次重建又被强行恢复成旧筛选
  - 回归脚本：`tools/verify_shelf_spinner.py`（最小 Python 模型复现 Spinner 生命周期，5 个场景：视图重建必填 / 选中态保留 / 同视图未变仍跳过重建 / 内容变化重建 / 空字典库）。
- **v3.5 修复：切 Tab 回书架整页空白**（用户反馈「点开 API 设置后回到书架页面时，书籍信息、分类栏、排序栏不显示」）。这是 v3.2 指纹优化的第二个盲区——`MainActivity.selectTab` 用 **`replace()`**，每次切 Tab 都**销毁重建** ShelfFragment 视图；而 `firstLoadDone` 是实例级字段（=true），指纹没变时 `onResume` 直接 return → **新视图的空适配器、空 Spinner 什么数据都拿不到** → 书籍/分类/排序全空白。API 设置流程对数据零改动（指纹必然一致），所以必现。**修复**：①新增 `viewRebuilt` 标志（`onCreateView` 置位）；②`onResume` 检测到视图刚重建时先调 `applyDataToView()`——用**实例级缓存**（`allBooks`/`locations`/`tagList`/`categoryList`/`channelList`/`countryList`，新增国家快照字段）直接灌进新视图（填 5 个 Spinner → 恢复筛选选中 → `applyFilters()` 提交适配器），**不查库、零开销**；③指纹校验照常异步做，数据真变了仍走完整 `loadData`。原则：**指纹优化省的是「查库」，不能省「给新视图喂数据」**。回归脚本：`tools/verify_shelf_rebuild.py`（时序模型 3 场景：首次加载→开 API 设置→回书架 / 筛选选中态保留 + 筛选结果正确 / 连续多次往返）。

- **v3.7**（versionCode 36）：修复「版次只填年，重开编辑页年框自动变成 `2022-|`」（用户反馈 + 截图）。**根因链**：①`joinEdition` 旧实现无条件 `y + "-" + m + "|" + n`，只填年时存成 `2022-|`（悬空分隔符）；②重开编辑页时 `fillEditionFields` 的正则 `^(\d{1,4})-(\d{1,2})\|(\d+)$` 要求月段至少 1 位数字，匹配不上脏串 → 走「自由文本兜底」把原文 `2022-|` 整串塞进年框。**修复**（逻辑收敛到 `BookSanitizer`）：①新增 `BookSanitizer.joinEdition(y,m,n)`——只在对应段有值时拼分隔符（只年→`2022`、年+月→`2022-5`、年+版→`2022|2`、三段全→`2022-5|2` 与旧标准格式一致）；②新增 `BookSanitizer.splitEdition(stored)`——宽容拆分（各段纯数字或空，兼容旧脏数据空段写法），自由文本返回 null 由调用方兜底；③新增 `BookSanitizer.sanitizeEdition(stored)`——可拆则重拼规整，并接入 `normalize()`（publishDate/printing 两字段），**存量脏数据在所有读取入口自动自愈**（详情页/统计/导出看到的都是干净值，编辑页重存后写回）；④编辑页 `fillEditionFields`/`joinEdition` 改为委托公共方法；⑤**脏检查同步修正**：已存脏数据的书拆分回显后未改动，拼回值（`2022`）与原存储值（`2022-|`）不等会误弹「未保存」提示——比对基准改为 `sanitizeEdition(存储值)`。回归脚本：`tools/verify_edition.py`（23 断言：拼接规则 / 拆分兼容 / 脏数据自愈 / 保存→重开→再保存闭环）全绿。
