# 小书房 · 发版记录

> 本页是交付物的**机器可比对**台账，两条用途：
> 1. `scripts/pack.ps1` 每次打包后拿这里的**上一条可交付行**做 SHA-256 与体积（±5%）比对；
> 2. `tools/check_doc_drift.py` 把它当文档之一，比对 versionName / versionCode / DB / 单测数字。
>
> **数字只能是实测值**：体积与 SHA-256 由 `Bookshelf/tools/check_release_package.py --apk <文件>` 读出，
> 版本与 ABI 由 `aapt dump badging` 读出，日期取 APK 文件修改时间。手写凭印象的数字不要进这张表。
> 新行加在表格末尾，不要重排历史行；交付目录里被判定「不可交付」的旧包也照实列出并标原因。

## pack.ps1 比对口径（重要）

- **SHA-256**：与「上一条**可交付**行」比。完全相同 → Fail（内容没变却重新发同号，或产物是旧的）。
- **体积**：相对「上一条**可交付**行」±5% 以内为 Pass，超出判 Fail 并说明差值。
  基准必须跳过不可交付行：5.9.5（37.12 MB）如果跟字面上一行 5.9.4（73.31 MB）比，会得到 -49.4% 的
  假告警；跟 5.9.0（37.05 MB）比才是 +0.19%。
- **扫描范围**：交付目录里全部 `XiaoShuFang-v*.apk` 逐个套同一判据，不能只判新产出的那一个——
  上一轮那两个 `.devtest` 包就是静静躺在交付目录里的例子。扫描用 `Get-ChildItem` 且**不带 `-Recurse`**，
  所以判定不过的包移进交付目录的同级子目录 `归档-不可交付/` 后不再计入（2026-11-10 把 v5.9.2 / v5.9.4 /
  v5.9 三个包归档，交付目录只剩 v5.9.0 与 v5.9.5）。归档不等于删除，文件都在，随时可取回。
- 新行由 `scripts/pack.ps1` 的判定输出手工补进表格（打包脚本不自动改文档），补完再跑
  `python -X utf8 tools/check_doc_drift.py`。

## 命名口径

v5.8.33 及以前用 `小书房-vX.Y.apk`，v5.9 起统一 `XiaoShuFang-vX.Y.apk`（拼音，避免中文路径在
CI / 传输环节被搞坏）。老命名的三个包本身是可交付的 release 构建，只是前缀不在 `XiaoShuFang-*`
扫描口径内；交付目录清理时按「保留最新可交付 + 保留一个最近老命名样本」处理，删哪些由人决定。

## 与其它文档的关系

  多大、哈希多少、能不能交付」。

  由 `tools/check_doc_drift.py` 从 `app/build.gradle`、`AppDatabase.java`、测试目录算出。
