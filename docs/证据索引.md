# 证据索引 · v5.9.5（2026-11-11 立，I2 · T5）

## 0. 这份文件解决什么

`dist/verify/v5.9.5/` 在**仓库外**（工作空间根 `小书架工作空间/` 不是 git 仓库，`Bookshelf/` 才是）。
换一台机器、或者只 clone 仓库，那 90 个文件一个都拿不到，只剩 `docs/改进方案-2026-11-10.md` 里
引用的那些数字——而数字脱离了原始输出，下一轮又得重新取证。

本文件是**那批证据的目录与可重建性清单**，它本身在仓库里，所以换机器也读得到。
它不搬证据本体（要不要搬见第 4 节，待用户裁决），只回答三个问题：
**哪个目录属于哪张卡 / 里面是什么 / 没了之后能不能用命令重新造出来。**

- 索引时点：2026-11-11，仓库 HEAD `d235bc9`，versionCode 139 / versionName 5.9.5 / DB v26。
- 实测规模：**14 个子目录、90 个文件、7 058 264 字节（6.73 MB）**。
- 复算命令：在工作空间根执行 `ls -1 dist/verify/v5.9.5/ | wc -l` → 14；
  `find dist/verify/v5.9.5 -type f | wc -l` → 90；`du -sb dist/verify/v5.9.5` → 7058264。
- **上面三个数是 11-11 的封条，已被后续三轮超出。当前规模与新增目录见第 6 节增补**，
  第 2 节那张表不改（它是当时的现场，改了就等于篡改封条）。

## 3. 索引过程中查出来的三件事（都是实测，不是推测）

### 3.1 三个目录是「无主证据」

`stats-3.1-before` / `stats-3.1-after` / `stats-3.1-cmp` **没有 README，也没有任何入库文档提到它们**
（`grep -rn "stats-3.1" docs/` 只命中本轮新写的文字）。能钉的只有时间戳：11-10 13:15 / 13:17 / 19:46，
落在 `ed26e56`（11-08 18:32）与 `f86b473`（11-10 16:10）之间，即**那批源码还没提交的工作区阶段**。
「3.1」这个编号来自对话侧的视觉清单，仓库里没有对应物，所以**本索引不替它编一个卡号**。

### 3.2 那一批是纯视觉改动，文案零变化（可复算）

四份可见文本改前改后**逐字一致**，9 张截图全部不同：

```
$ diff -rq stats-3.1-before stats-3.1-after
  Files .../books_00.png and .../books_00.png differ      （共 9 行，全是 .png）
$ cat stats-3.1-before/*_all.txt > /tmp/b.txt
$ cat stats-3.1-after/*_all.txt  > /tmp/a.txt
$ diff /tmp/b.txt /tmp/a.txt | grep -c "^[<>]"
  0
```

行数也对得上：books 90/90、reading 43/43、purchase 48/48、lend 52/52。
**结论**：这一步只动了间距与字阶，没动任何数字或文案——这正是「搬运不改数字」想要的证据形状。

### 3.3 两处关键结论目前不可复算，属真债

| 结论 | 出处 | 为什么复算不了 |
|---|---|---|
| 61 个硬吞站点、A8/B19/C34 分级 | 卡 6 | 五分类器（EMPTY/COMMENT_ONLY/RETHROW/REPORTS/SILENT_CODE）没入库，`tools/audit_cn_and_catch.py` 是另一套口径 |
| 改前 66 条数字逐条命中、改前独有 0 条 | 卡 2 | `fp.py` 只存在于证据目录里，仓库无后继；dump 原件一旦丢失就无法重算 |

这两条不是「忘了写命令」，是**脚本本身没进仓库**。要关闭，得把分类器与 `fp.py` 收进 `tools/`
（属清单外，本轮只登记）。

## 4. 要不要把证据本体收进仓库（待用户裁决）

实测体量分布：

| 类别 | 目录数 | 字节 | 占比 |
|---|---|---|---|
| 截图/节点 dump（`stats-3.1-before/after/cmp`、`stats-ab-card2`） | 4 | 6 736 991 | **95.4%** |
| 纯文本（其余 10 个目录） | 10 | 321 273 | 4.6% |

三个选项：

- **甲｜只收文本（推荐）**：10 个目录、314 KB 进 `Bookshelf/docs/证据/v5.9.5/`，截图留仓库外。
  代价：换机器后看不到排版对拍图；收益：clone 只胖 314 KB，而 A 档结论全部可复算。
- **乙｜全收**：6.73 MB 进仓库。代价：每次 clone 都背 6.4 MB 截图，且截图价值随版本推进迅速衰减；
  git 历史里二进制不可 diff，以后每轮都再叠一份。收益：C 档现场也保住了。
- **丙｜全不收，只留本索引**：0 字节增量。代价：C 档证据（卡 6 分级、卡 2 指纹、3.1 裁切图）
  换机器即永久丢失，第 3.3 节那两条债永远关不掉。

**本轮不做任何搬运**：约束是不 commit、不 push，而「收进仓库」只有 commit 之后才成立。
本文件是甲/乙两个选项的**前置第一步**——先有清单，才谈搬哪些。

## 5. 换机器之后怎么用这份索引

1. 先跑 A 档命令（第 2 节最后一列），能复算的当场复算，数字对不上就是真漂移。

   不许拿它冒充旧证据，必须重新标时点。

   不许把记载当实测重新写一遍。

### 7.3 新增一档：**A′ 可复算，但依赖仓库外的本机资产**

第 1 节的三档不够用了。字体那三个脚本与产物：

- **在本机**：跑一遍就得到**同样的字节**（输入 VF 固定、fontTools 版本固定、子集字符集由源码算出）→ 像 A；
- **换机器**：`C:/Windows/Fonts/NotoSerifSC-VF.ttf` **不一定存在**，脚本也没进 `tools/` → 像 C。

所以标 **A′**，含义是「**可复算，但复算的前提是一份不在仓库里的本机文件**」。
**关闭这条债的办法不是把 25 MB 字体收进仓库**（OFL 允许，但会让每次 clone 都背 25 MB），
而是：① 三个脚本收进 `tools/`；② 在文档里写清「需要用户自备 Noto Serif SC VF，SIL OFL 1.1」。
**本轮只登记，不搬**（与 §6.4 同纪律）。
