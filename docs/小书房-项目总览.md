## 1. 项目定位

原生 Android（Java + ViewBinding）单模块应用，包名 `com.bai.bookshelf`，工程目录 `Bookshelf/`。
  
由微信小程序「我是小书房啊」重构而来，定位：**个人/家庭纸质书收藏管理**。
  
技术栈：Java 17、Room、CameraX + ML Kit（扫码）、Glide、Retrofit+Gson（ISBN 查询）、Material 3，无其他第三方依赖（Excel 读写为零依赖自实现）。

## 2. 构建方式（重要）

```
cd "D:/腾讯/WorkBuddy空间/小书架工作空间/Bookshelf"
JAVA_HOME="D:/tools/jdk-21.0.2" sh ./gradlew --offline -q :app:assembleDebug --console=plain
```

- **JDK 口径：编译目标 17、工具链 21**（卡 A2 定稿）。`app/build.gradle` 的 `compileOptions` 保持
  `VERSION_17`（source/target 都是 17），本机与 GitHub Actions 都用 **JDK 21** 跑构建：本机走环境里的
  `JAVA_HOME`（当前 `D:\tools\jdk-21.0.2`），CI 用 `setup-java` 的 `java-version: 21`。
  以前 ci.yml 写的是 17，与本机不一致——**21 是这套工程实测跑通的（本工程所有 APK 都由 21 产出），
  17 工具链在本机没有对应 JDK、从未验证过**，所以口径统一到 21，而不是让 CI 去跑一条本机没跑过的组合。
  不要新增 `toolchain { languageVersion }` 声明：那会让 Gradle 联网自动下载 JDK，与「离线可构建」冲突。
- **工具链位置一律推导，不写死**：`scripts/pack.ps1` 现在按 `gradlew.bat`（Windows wrapper）→ 环境变量
  `JAVA_HOME` → `local.properties` 的 `sdk.dir`（退到 `ANDROID_HOME` / `ANDROID_SDK_ROOT`）取；
  `-GradleExe / -JavaHome / -SdkDir` 只做临时 override，不再是默认值。换机器只要 `local.properties` 和本机
  `JAVA_HOME` 对，脚本不用改。
- 项目路径含中文，依赖 `android.overridePathCheck=true`（gradle.properties 已配）。
- 产物与交付：跑 `scripts/pack.ps1`——`assembleRelease` → aapt 校包名 / ABI / 版本号 → 与
  `docs/发版记录.md` 的**上一条可交付行**比 SHA-256（不能相同）与体积（±5%）→ 扫交付目录里全部
  `XiaoShuFang-*.apk`（旧包混进 .devtest / x86 会被逐个点名）→ 全部通过才复制成
  `XiaoShuFang-v{versionName}.apk` 并打印 SHA-256 与体积。退出码：0 已交付；1 硬失败（环境/构建/这个包本身
  不可交付）；N>1 = 判定失败条数，**此时不产出文件**。**不要再手工复制 apk**（v5.9.5 起这是唯一交付路径）。
- 当前版本：versionCode 139 / versionName "5.9.5"（`app/build.gradle`），Room 数据库 v26（v24 补索引、v25 打卡表 `check_ins`、v26 打卡行加 `seq` 归入阅读轮次）。**v4.23 起交付物切换为 release 构建**（`assembleRelease`，同 debug 签名，`debuggable=false` + 强制 https；debug 构建仍用于抓包调试，也是真机灌测试数据时 `run-as` 的唯一入口）。

**迁移铁律（血泪教训）**：

- Java String 字段在 Room 是**可空 TEXT**，迁移 SQL 只能写 `TEXT DEFAULT ''`，绝不能 NOT NULL（v1.1 曾因此闪退重建表）
- int/boolean 基本类型才是 NOT NULL；Long（如 locationId）必须可空 INTEGER
- **正因为 String 列可空，读出来的老数据可能是 null**：凡是拿表单值和 book 字段做比对的地方都要过 `nz()`（BookEditActivity 踩过：脏检查误判导致「没改也弹未保存框」）
- 所有迁移注册在 AppDatabase（MIGRATION_1_2 … 9_10）+ BookshelfApp，保数据升级，禁止 fallback 到 destructive（开发兜底目前开着，发布前可考虑关）
- 表间关系用「名称快照 + 传播器」：书籍存名称字符串；TagPropagator/CategoryPropagator 及国家重命名/删除时遍历书籍同步（books.country 的联动目前写死在 BookEditActivity 的国家选择器里）

## 7. 已知坑与开发约定
1. **lambda 捕获**：被 lambda 引用的局部变量必须 effectively final——需要中途赋值的抽成方法（AddBookHelper.findDuplicate 教训）。
2. **异步 UI 回调**：Fragment 异步回调先判 `b == null`/`isAdded()`；Activity 判 `isFinishing()/isDestroyed()`（导入闪退教训）。
3. **文件选择器**：用 OpenDocument 而非 GetContent（部分 ROM 兼容性）；launch 包 try/catch。
4. **Spinner 取值**：渠道类联动下拉取 `getSelectedItem()` 显示文本，不按下标查异步列表（错位教训）。
5. **书名展示**：一律经 BookText，防 API 标题自带书名号。
6. **逐本信息交互**：折叠/二级页在**编辑页**；详情页是直接展开（含第 1 本，多本时每行末尾带借出/归还按钮）。
7. **用户工作流**：编号列表提需求 → 实现 → 打包 → 真机验证 → 编号反馈（含截图）。UI 细节（间距/角标/分割线/单位）要求精细；金额 BigDecimal 两位小数；中国市场配色（涨红跌绿，暂未涉及行情类 UI）。
8. Excel 导出 28 列含「拥有数量/各本存放位置」；导入按表头名匹配——**注意 book_copies 与 note_images 目前不参与导入导出**（未来需求点）。
9. **SAF 一次性授权**：导出选文件夹后即时写入即可，不要 takePersistableUriPermission（会占系统授权配额）；只有自动备份文件夹才需要持久化授权。
10. **图片一律落盘**：相册选到的 Uri 权限会失效，任何选图（封面/备注图片）都要复制到 filesDir 下再存路径；放弃保存/删书时记得清掉文件。
11. **库 attr 必须走库的 R**（v2.5 教训）：AGP 默认 `nonTransitiveRClass=true`，app 的 `R.attr` **不含** appcompat/material 的属性——代码里取 `colorPrimary` 要用 `androidx.appcompat.R.attr.colorPrimary`（`colorSecondary` 在 `com.google.android.material.R`），已封装为 `ThemeManager.ATTR_COLOR_PRIMARY` / `ATTR_COLOR_SECONDARY`；XML 布局里用 `?attr/xxx` 不受影响。
12. **新增 Activity 必须继承 BaseActivity**（v2.5 起）：否则 `ThemeManager.applyTheme` 不会挂载，该页主题色不跟随用户选择。
13. **SQL 的 DISTINCT 不作用于表达式**（v3.2 实测踩坑）：写 `SELECT DISTINCT TRIM(country) FROM books` 时，DISTINCT 比较的是**原始列**，「中国」与「 中国」会变成两条记录。正确写法是用子查询让 DISTINCT 作用于 TRIM 的结果：`SELECT DISTINCT country FROM (SELECT TRIM(country) AS country FROM books WHERE ...) ORDER BY country ASC`。
14. **指纹类聚合要注意精度**（v3.2 踩坑）：`SUM(CAST(listPrice AS INTEGER))` 里 `CAST(45.5 AS INTEGER)` 与 `CAST(45.9 AS INTEGER)` 同为 45，几角钱的调价检测不到；要写 `SUM(CAST(listPrice * 100 AS INTEGER))`。另外空表时所有 SUM 为 NULL，必须用 `IFNULL(...,0)` 兜住，否则指纹返回 null 会被误判成「数据变了」。
15. **纯 python heredoc 批量改文件易翻车**：三引号紧跟 `-` 会被当成减法（报 `unsupported operand type(s) for -`）；替换 Java 标识符会连 **import 语句里的包名**一起替换掉（编译报「需要'.'」）；替换方法名会把**方法定义**也改掉。改 Markdown 与 Java 源码优先用 Edit 工具。
16. **验证不能只靠读代码**：v3.0 的「xlsx 封面不导出」与 v3.2 的两条 SQL 都出现过「读代码觉得没问题、实测才暴露」的情况。现在新增 SQL 逻辑写 JVM 单测（纯查询用 sqlite-jdbc 复现，见坑 49）、DAO 行为写 androidTest，OOXML 结构改动必须真导一个「部分书无封面」的样本出来核对图片张数与序号——这类错位脚本读代码读不出来。
17. **Fragment 的实例级状态与视图生命周期不对齐**（v3.3 踩坑，最容易复发的一条）：`onCreateView` 每次都新建视图，但 Fragment 的**字段跨视图重建存活**。凡是「拿字段里的旧值判断是否要重建视图控件」的优化（v3.2 的 Spinner cache 就是典型），一旦遇上视图重建就会永久失效——控件是空的、缓存说「没变」→ 永远不填充。**铁律**：任何跨视图重建需要保留的缓存，必须在 `onCreateView` 开头显式复位（或以「控件 adapter 是否为 null」作为兜底判据），并且发版前把「首次加载 → 切 Tab → 回来」在真机上走一遍。
18. **Retrofit `@Url` 解析失败会静默回退到 baseUrl**（v3.4 踩坑）：用 `@Url` 传全路径时，若字符串不是合法绝对 URL（如 `http&https://...`、缺协议头），Retrofit 不报错，而是把它当相对路径拼到占位 baseUrl 后面——本工程是 `https://placeholder.local/`，最终报「Unable to resolve host placeholder.local」，完全看不出是用户填错了地址。**铁律**：用户可编辑的 URL 必须在入口处规整 + 用 `okhttp3.HttpUrl.parse` 校验（与 Retrofit 同一解析器），并在发请求前兜底检查。
19. **「按需刷新」优化的省略范围必须与视图生命周期对齐**（v3.5 踩坑，v3.3 坑 17 的延伸）：本工程 Tab 切换用 `replace()`，**每次切 Tab 都销毁重建 Fragment 视图**。指纹一致时可以省「查库 + 解析」，但**新建的适配器/Spinner 是空的，必须把实例级缓存的数据重新灌进去**（`applyDataToView()`），否则整页空白。判断口诀：优化跳过的每一步，问一句「新视图需要它吗？」——跳过查库可以，跳过喂数据不行。（v4.1 起 Tab 改 `add` + `show/hide`，视图不再每次重建，这条按「实例级字段 vs 视图生命周期」的通用形态保留。）
20. **组合字段的「拼接」与「拆分」必须成对设计、互相兼容**（v3.7 踩坑）：版次三段式（年/月/版）拼接时无条件加分隔符，就会产生 `2022-|` 这种悬空分隔符的脏串；而拆分端正则若比拼接格式严格，脏串就会走「自由文本兜底」整串塞回第一个输入框。**铁律**：①拼接只在对应段有值时加分隔符；②拆分要宽容（各段允许为空），并把拼接/拆分/规整三者收敛到同一个工具类（本工程是 `BookSanitizer.joinEdition/splitEdition/sanitizeEdition`）；③凡是「存储值 → 回显 → 再保存」的字段，脏检查的比对基准必须是**规整后的存储值**，否则存量脏数据会误触发「未保存」提示。等价断言在 `BookSanitizerTest`（`editionJoinAndSplit` / `sanitizeEditionRemovesDanglingSeparators`）。
21. **自绘 View 的命中测试必须复用绘制坐标**（v4.20 踩坑）：`PurchaseHeatmapView` 原先绘制用 `gap + cellSize * col`（列间连续），而 `hitTest()` 用 `gap + col * (size + gap)`（列间带 gap）→ 命中框与实际色块错位，点哪儿都不中。**铁律**：自绘 View 在 `onDraw` 里把每个可点击图元的 `RectF` 记进列表，点击时直接遍历命中，**不要在 onTouchEvent 里另写一套坐标公式**；两套公式必然漂移。
22. **可点区域不能小于 ~10dp**（v4.20 踩坑）：年热力图 53 列若压到屏幕宽，每格只有 4.8dp，手指根本点不中（实测差 1.4px 就落在格外）。**铁律**：密集网格要么固定格子尺寸 + 外层 HorizontalScrollView 横向滚动，要么在命中测试里做容差外扩（本项目两种都用了：固定 12dp + 1dp slop）。
23. **LinearLayout 的 weight 分配陷阱（v4.21 踩坑）**：做「进度条 + 底槽」两段式权重条时，底槽的 `layout_weight` **不能置 0**——LinearLayout 里唯一有非零 weight 的子 View 会独占全部宽度，于是「2 本」和「4 本」画出来一样长。**铁律**：底槽 weight = 最大值 - 当前值，与主色段一起瓜分槽宽；两段都要有非零 weight。
24. **给 LinearLayout 设 OnClickListener 不等于可点击（v4.21 踩坑）**：LinearLayout 默认 `clickable=false`，`setOnClickListener` 后 uiautomator 仍报 `click=false`，且 DOWN/UP 事件能到但 `performClick()` 不触发（表现为「怎么点都没反应」）。**铁律**：要整行可点的 LinearLayout，XML 里必须写 `android:clickable="true"` + `android:focusable="true"`。
25. **`android:maxHeight` 对 NestedScrollView 无效，且必须在 show() 前设高度（v4.22 踩坑）**：底部面板里放全部年份的日历块时，内容把面板撑得极高，底部钉住的详情条被挤出屏幕。`android:maxHeight` 只对 TextView/ImageView 生效，滚动容器只能**代码里设 `LayoutParams.height`**；而且必须在 `dialog.show()`（触发测量）**之前**设——show() 之后再设测量已过，不生效。**铁律**：BottomSheet 里固定高度的滚动区 = 屏高百分比，用代码设 LayoutParams，且在 show() 前设。
26. **面板标题不要由调用方拼好（v4.22 踩坑）**：标题里带「当前周期」时，若由调用方拼接，切粒度后面板内部状态变了、标题却不变（表现为切到「按年」还显示「2026/10」）。**铁律**：面板自己管标题的动态部分（`renderTitle()`），调用方只传静态基名。
27. **文字标签的热区不能只有文字宽度（v4.22 踩坑）**：迷你年视图的「10月」标签热区按 `measureText` 算只有 ≈20dp，手指点不中。**铁律**：可点文字的热区至少扩到所在块宽的一半，或做容差外扩（≥10dp 见坑 22）。
28. **show/hide 切 Tab 不触发 onResume（v4.23 踩坑）**：MainActivity 用 add+show/hide 复用 Fragment，切 Tab 只有 onHiddenChanged。后台线程（如启动时自动备份）晚于 onViewCreated 写的状态，副标题/计数会停留旧值。**铁律**：Fragment onVisible()（onResume 与 onHiddenChanged(!hidden) 共用入口）里刷新所有「实时状态行」，不要只靠 onViewCreated。
29. **删除级联宁可逐行删，不要按前缀整批删（v4.23 踩坑）**：副本全删全插场景下，按 `copy:{bookId}:%` 前缀 DELETE 会把保留副本的历史图记录一并删掉，而这些图不在本次 UI 的 copyImages map 里、无处重建 → 静默丢数据。**铁律**：先查出旧集合，按「超出新范围的行」逐行 deleteById + 删文件。
30. **CardView 的底色不能用 `itemView.setBackgroundColor()` 改（v4.24 踩坑）**：书架列表项根布局是 `androidx.cardview.widget.CardView`，`setBackgroundColor()` 会把 CardView 内部的 RoundRectDrawable 直接换成纯色（透明），圆角白底与描边一起消失，表现为「列表卡片没有底色」。**铁律**：CardView 底色用 `setCardBackgroundColor()`；叠加选中态就切底色（本项目用 `?attr/primary_container`），不要动 `setBackgroundColor()`。
31. **BottomSheetDialog 半展开态可能出现绘制/触摸错位（v4.25 真机踩坑）**：录入方式面板用 `BottomSheetDialog` 时初始停在半展开，内容按展开位置布局、绘制却被上移；真机上点第三行会落到第一行、点第一行会关闭面板。`STATE_EXPANDED` 在真机上未纠正位移。最终改用**底部对齐的普通 `Dialog`**：透明 window + `Gravity.BOTTOM` + `match_parent/wrap_content` + `bg_bottom_sheet` 圆角背景 + 底部 inset，绘制与命中区域一致。**铁律**：自定义底部面板出现「看得见点不到」时，优先怀疑 BottomSheetBehavior 的半展开/窗口动画位移，改用普通 Dialog 或完全展开并实测触摸区。
32. **真机灌测试数据要用 debug 包，交付的 release 包 `run-as` 会拒绝（v4.26 踩坑）**：v4.23 起交付物是 release（`debuggable=false`），`adb exec-out run-as com.bai.bookshelf cat databases/bookshelf.db` 直接报 `package not debuggable`（重定向会把报错文本写进本地文件 → 打开时报 "file is not a database"）。流程：①先覆盖安装 `app-debug.apk`（同签名，数据保留）；②`exec-out run-as ... cat` 拉库 → 本地 python sqlite3 改数据 → 推回；③推库注意 `/sdcard` 的文件属主是 shell、`run-as cp` 读不了（Permission denied），要先 `cp 到 /data/local/tmp` 再 `chmod 644`；④测完删测试行、`VACUUM`、删 `-wal/-shm` 再推回，最后重装 release 交付包。**铁律**：设备交付包绝不 `rm` 数据库目录，所有写入走「拉了改、改完推」，随时可回退。
33. **底部 Dialog 在个别 ROM 上会被解析成「WRAP_CONTENT + 右侧重力」（v4.27 用户真机反馈）**：`new Dialog(activityContext)` + `window.setLayout(MATCH_PARENT, WRAP_CONTENT)` + `setGravity(BOTTOM)` 在大多数设备上正常，但个别 ROM 上窗口实际宽约 331dp、从屏幕中偏左弹出且右侧被裁（表现为「面板不是全宽、整体右移」）。修复套路：①在 `setOnShowListener` 里用**像素宽度**钉住窗口（`decor.getWidth()` 减掉左右 systemBars/displayCutout inset），`gravity = BOTTOM|START`、`lp.x = 左侧 inset`；②内容根 `setMinimumWidth(可用宽度)` 兜底（宽度真被忽略时内容也能撑满）；③窗口动画换成纯淡入淡出（`Animation.Bookshelf.Sheet`），排除系统默认滑入/缩放动画在展开过程中造成的横向位移。**铁律**：自定义底部面板不要只依赖 `MATCH_PARENT`，宽度和横向位置都显式钉死，动画只做透明度。
34. **Dialog 里套 ScrollView 的三个坑（v4.28）**：①窗口给内容的宽度是 **AT_MOST**，ScrollView 里的 `match_parent` 子布局会被量成「自然宽度」→ 面板只有一半宽；要把内容 `LayoutParams.width` 钉成窗口像素宽。②`getWindowVisibleDisplayFrame()` 会扣掉「仍显示着的输入法」，用它算高度上限会把面板算矮、最后一行贴到窗口底；高度上限改用 decor 高度。③uiautomator 的 bounds 会被裁到窗口可见区域，看起来像「第三行被裁」——判断是否真裁切要看截图而不是 bounds。
35. **uiautomator 报「保存按钮只有 27dp」是假象（v4.29 结论）**：固定底栏贴在窗口底部时，uiautomator 的 bounds 会被裁到窗口可见区域（手势条以上），48dp 的按钮只报 74px、底栏只报 99px。判断真实高度要看截图或用 `dumpsys`；真 bug 是**键盘弹出时窗口不缩放**——Android 15+ 强制 edge-to-edge 后 `adjustResize` 失效需自行处理 ime inset，低版本如果没写 `adjustResize` 会走 pan，按钮被键盘盖住。编辑页现在两者都配齐。
36. **深色主题要扫三类写死颜色（v4.31）**：①布局里的 `@color/text_main|text_sub`、分隔线/选中底色；②Java 里 `ContextCompat.getColor(R.color.text_main)`；③矢量图标里写死的描边色（ic_search/ic_close 需改黑色 + 布局 tint）。另外主题主色若同时用于「表头背景 + 数字文字」，深色下必然二选一难看——夜读把 primary 设为暗金、`colorOnPrimary` 设为深墨，并把工具栏/FAB 的着色改为 `?attr/colorOnPrimary`。还有：`GridLayout` 的 `rowCount` 小于实际行数会直接抛 `IllegalArgumentException`（加第 7 套主题时踩到）。

37. **跨 Activity 的共享元素过渡不是免费的（v4.39 实测）**：书架 → 详情的封面 `shared element` 过渡需要和目标窗口做一次位置握手，`postponeEnterTransition` 期间整页不可见——真机 `Displayed` 从 156~190ms（无过渡）被推到 256~274ms（有过渡），点书手感明显发滞；`postpone` 去掉也救不回来，握手成本在系统侧。**铁律**：列表→详情的「首屏速度」优先级高于封面形变时，不要用 shared element；先用 `adb logcat | grep Displayed` 量出基线再决定。另外：①详情页信息行用代码构建（`InfoCell`）比 XML inflate 快一个量级，且能做「复用只改文字」；②`RecyclerView`/列表之外的自建列表（如逐本信息）不要 inflate 隐藏项，数量一多就是几十 ms；③详情页 `reload` 的 N+1 查询（逐本查地点、逐条查备注图）要收敛成「一次查全 + 内存分组」。

38. **自定义全屏底部 Dialog 的系统栏黑边（v4.40 实测）**：自己 new 出来的 Dialog 窗口会被系统栏切掉一块，导航栏区域还会被涂成黑色——面板贴在底部时，与手势条之间露出一条黑边（录入方式面板一直有，只是没人注意）。修复：`InsetsHelper.makeSheetWindowFullScreen(window)`——`FLAG_DRAWS_SYSTEM_BAR_BACKGROUNDS` + 状态栏/导航栏透明 + `setNavigationBarContrastEnforced(false)` + `setDecorFitsSystemWindows(false)`（API<30 用 systemUiVisibility 的 LAYOUT_*）。**铁律**：自定义底部面板 = 全屏窗口铺到底 + 内容自己补 `systemBars().bottom` 内边距，不要指望窗口自动避让。

39. **搜索索引要离线建、输入路径只做 contains（v4.41）**：拼音转写（ICU `Han-Latin`）单字成本不低，21 本书约几 ms、1000 本书会到数百 ms——**绝不能在按键回调里做**。做法：数据推送后在 io 线程给每本书算一条 haystack（归一化原文 + 全拼 + 首字母），UI 侧只 `contains`；索引未就绪时用原文兜底现场归一化。另有两条 UI 经验：①「清除/清空」这种可点动作不要写成同一 TextView 里的 ClickableSpan——`singleLine + ellipsize` 会把末尾链接整段吃掉，必须拆成独立按钮固定占位；②`input text` 在模拟器 IME 上偶尔会吞首字符或重复，自动化验证前先把光标位置与已输入内容确认清楚。

40. **Room 迁移的列定义必须与实体生成的定义逐字一致（v4.42 实测）**：`public String phone = ""` 这种字段 Room 生成的是**可空** `TEXT`，即使加了 `@ColumnInfo(defaultValue = "")` 也是 `phone TEXT DEFAULT ''`（没有 NOT NULL）。迁移里写成 `ADD COLUMN phone TEXT NOT NULL DEFAULT ''` 会通过 ALTER、但随后被 Room 的 schema 校验判为「Migration didn't properly handle」并回滚（真机表现是应用起不来、DB 仍是旧版本）。**铁律**：先看 `app/schemas/.../{version}.json` 里该表的 `createSql`，迁移 SQL 照抄列定义；另外 Room 默认 WAL，拉库核对必须连 `-wal` 一起拉（或先 force-stop 再拉），否则看到的是旧数据。
41. **脚本化整文件替换会「静默删代码」，编译期发现不了（v4.46 埋雷、v4.49 才暴露）**：v4.46 用 Python `str.replace` 修重复块时，把 `ScanActivity` 的 `onCreate` / `setContentView` / 相机权限 / `startCamera` / 条码分发 / 手动输入 / 相册识别整段一起删掉。因为 Activity 有默认 `onCreate`，**Gradle 照常编译通过、release 正常打包**，只是页面全黑；这个包被当作交付物发出去，直到 v4.49 想读清单「空白页」排查时才在模拟器上发现是扫码页。**铁律**：①改大文件前先复制一份 `.bak` 或确保可回滚；②任何按片段替换的脚本改完必须对比方法清单（`grep -nE "^\s{4}(public|private|protected|@Override)"`），关键页面要补一条「onCreate/setContentView 是否存在」的体检；③交付前对**每个入口页**做一次真机/模拟器点开验证，不要只测改动的那个页面；④Activity 缺 `setContentView` 不会报编译错，可用 `for f in $(find ... -name "*Activity.java"); do grep -q setContentView $f || echo $f; done` 快速审计（继承基类设内容的除外）。

42. **ML Kit 文字识别的 16KB 与「封面标题」启发式（v4.51 实测）**：`com.google.mlkit:text-recognition-chinese:16.0.1` 的 native 库已 16KB 对齐（arm64/armv7/x86/x86_64 的 PT_LOAD p_align 都是 0x4000，`zipalign -c -P 16` 通过），可以放心用 bundled 版本；但 OCR 库每个 ABI 约 7~11MB，release 必须用 `ndk { abiFilters 'arm64-v8a','armeabi-v7a' }` 收口（否则 APK 55MB+）。识别结果不要「取第一行」当书名——封面顶部常有「长篇小说/丛书名」，应按 `Text.Line.getBoundingBox().height()` 取字号最大的候选；作者/出版社用行级规则（`xx 著/编/译`、`作者：`、含「出版社」），并对常见误读（著→菁/箸、社→杜、出版社→出版杜）做容错，否则真实封面识别率会很难看。

43. **`new StringBuilder(int)` 是容量构造器（v5.8）**：`new StringBuilder(year)` 会把年份当成初始容量，结果是个空串——拼数字前必须 `new StringBuilder().append(n)` 或 `String.valueOf(n)`。这类 bug 编译与运行都不报错，只有断言文案的单测能抓出来。

44. **哨兵默认值不能同时当累加器；金额格式化要按量级给精度（v5.8）**：`Rating.average` 用 -1 表示「无数据」却又被 `+= v` 累加，总分被吃掉 1 分——累加用局部变量，最后再赋给对外字段。同理 `Spend.discount/perPage` 默认 0 会让界面显示「0 折 / 每页 ¥0」，必须默认 -1 并在 UI 里说「数据不足」；`¥%.0f` 把每页几分钱抹成「¥0」，小于 10 块要用两位小数。

45. **基于阅读日历的派生指标必须先按目标年截断（v5.8）**：「在读且没填结束日期」的书会把日键一直铺到今天，热力图要的就是这个语义，但习惯类指标不截断就会算出「7 月读了 155 天」（五个七月）、「当前连着 1627 天」。任何从 `ReadingCalendar` 日键派生的数字都要先按年/窗口过滤，并在界面上用一行说明交代推算依据。

46. **同一个词在两张卡里必须是同一个数（v5.8）**：「今年花销」一度在洞察卡按种、趋势卡按册，屏幕上同时出现 ¥366 与 ¥381。花费一律按册（`purchasePrice × max(quantity,1)`，借阅/赠书不计），并补了回归单测「趋势与同比的今年花销必须一致」。另注意**按时归还率是比例不是中位数**——对 0/1 序列取中位数会得到 1.0 的假象，必须 `onTimeCount / onTimeSample`。

47. **真机验证的三条现场纪律（v5.8）**：①子代理给出的审计结论必须逐条 grep 核实再采纳（一轮审计的三条首要建议里有两条是假的）；②MIUI 上 `uiautomator dump` 会抛 `theme_compatibility.xml` ENOENT 拿不到 XML，只能 `screencap` 目检，而**小字文案必须先用像素亮度扫描定位文字行、再切 ≤450px 宽的窄条放大 2~3 倍来读**——直接看整张缩放截图会「读」出代码里根本不存在的文案；③改过系统设置要恢复（`font_scale` 写回 1.0、`screen_off_timeout` 写回 60000），清理 `/sdcard` 截图不要用 `f*.png` 这类通配符，会连带删掉别的会话留下的文件。
48. **Room 只在实体声明了默认值时才校验默认值（v5.8 迁移测试实测）**：实体的 `String` 字段没有 `@ColumnInfo(defaultValue)` 时，导出的 schema 里 `dflt_value` 是 null；迁移写成 `ADD COLUMN x TEXT DEFAULT ''` 也能通过 Room 的校验（v19→20 的借阅日期三列就是这样，真机升级一直正常）。写迁移冒烟测试时如果严格比对默认值，会得到一堆假失败——比对规则要照抄 Room：默认值只在「期望侧有值」时才比。类型与非空则必须逐字一致。
49. **纯 JVM 也能跑真 Room 迁移（v5.8 的做法）**：本项目的迁移只调 `execSQL`，于是可以用 `java.lang.reflect.Proxy` 造一个 `SupportSQLiteDatabase` 薄壳把语句转给 sqlite-jdbc（`testImplementation 'org.xerial:sqlite-jdbc'`），事务方法直接放行、其余方法返回类型默认值。比实现整个接口（40+ 空方法）省事，也不会因为 androidx 升级接口而编译失败。旧库用 `app/schemas/<version>.json` 的 `createSql` 直接建（记得把 `${TABLE_NAME}` 换掉），目标库同样建一份，两者 `PRAGMA table_info` 一比就知道迁移写漏了什么。

50. **量词只许「种 / 册 / 笔」，别再把「本」写进文案（v5.8.1）**：books 表一行是「种」，实物是「册」，借阅/摘抄记录是「笔」。全部走 `util/Units`（`titles/copies/records/holdings`），趋势图单位、扫描计数、批量提示、空态、分享卡都已改用；`grep -rn '本"'` 是回归手段。**唯一例外是 Excel 导入的表头「各本存放位置」**——那是老导出文件的数据键，改了旧文件就导不进来，所以只在读取侧保留。

51. **自绘 View 必须接下 ACTION_DOWN，否则父级 ScrollView 会吃掉整次手势（v5.8.2 实测）**：`CategoryTreemapView` 原来只在 ACTION_UP 里做命中判断、DOWN 交给 `super.onTouchEvent`（不可点击时返回 false），父级 ScrollView 接管后 UP 永远到不了，真机表现就是「点一块没反应」。正确写法：DOWN 命中格子时返回 true，MOVE 超过 8dp 时 `requestDisallowInterceptTouchEvent(false)` 并返回 false 让页面继续滚动，UP 再判命中。**凡是在 ScrollView 里做自定义点击区域，都要走这套**。

52. **回滚前先确认「原库真的被挪走了」（v5.8.2 设计时踩到）**：恢复失败的回滚如果无条件 `delete(dbFile)` 再换回原库，那么失败发生在「还没挪旧库」的阶段（比如 close 就抛了）时，删掉的就是唯一一份好数据。回滚必须写成「只有在 `broken-*` 存在时才删新库并换回」，否则不动 `dbFile`。

53. **RemoteViews 不能给 ProgressBar 染色，也不能在 XML 里引用 `?attr`（v5.8.14）**：`setProgressTintList` 的参数是 ColorStateList，不在 RemoteViews 方法白名单里；`setInt(..., "setProgressTintList", color)` 会找不到方法而整次更新失败。小组件进度条改为在 `build()` 里用 Canvas 画 480×24 Bitmap 再 `setImageViewBitmap`；背景按主题切 7 个 shape drawable（`setInt(..., "setBackgroundResource", id)`），文字色用 `setTextColor`。`values-night` 只负责「小组件还没收到首次更新」时的首帧，App 主题仍由 ThemeManager 决定，两者不要混成一个。

54. **squarify 的「短边铺法」轴向最容易写反（v5.8.15 离屏渲染才看出来）**：`side = min(rw, rh)` 是这一行/列**排布方向的长度**，`strip = 行面积 / side` 是**垂直方向的厚度**。短边是高度时必须竖着铺一列（项沿 y 排、列宽 = strip），写成横着铺会让 `strip` 按错误的边算出来，结果条带厚度大于剩余高度、后面的块直接画到框外——屏幕上就是「8 个分类只看得见 3 块」，而数据、面积、标签全都没报错。自绘图表建议一律配一条**离屏渲染测试**（measure/layout/draw 到 Bitmap + 逐色扫像素），比截图更能定位这类问题。顺带：块上文字别写死白色，用 `ColorUtils.calculateLuminance` 对白字/墨字各算一次对比度取高的，暗金这类中亮度底色白字只有 2:1。

55. **仓库里的校验脚本只有四条（v5.9.5 起，卡 A 整改后）**：`tools/check_activities.py`（每个 Activity 的 `setContentView` 是否可达，坑 41 的自动版）、`tools/check_release_package.py`（APK 的包名 / ABI / 版本名核验，与 `scripts/pack.ps1` 同一套判据）、`tools/check_doc_drift.py`（`docs/` 三份文档的数字必须等于代码里的数字）、`tools/selftest_checks.py`（负向自测：前面三条喂错路径时必须拿到判定性的非 0）。前三条默认「扫到 0 个 / 比到 0 处」也算过——v5.9.5 那次 CI 假绿就是这么来的，现在一律 `exit 2`；判定性非 0 由第四条守着（argparse 的 usage 退出码也是 2，所以自测里单独识别，不算拦住）。`.github/workflows/ci.yml` 把四条都挂上，但**这条 CI 至今一次都没跑过（Actions 历史为 0），状态是「待上线」，取到首次绿色运行前不要当已生效用**；本地 `python -X utf8 tools/<名字>` 单跑即可。**旧文档里出现的 `tools/verify_*.py` 十一条（verify_shelf_sql / verify_xlsx_image / verify_shelf_spinner / verify_shelf_rebuild / verify_reactive_shelf / verify_two_stage_shelf / verify_tabs_restore / verify_tab_switch / verify_edition / verify_date_order / verify_douban）都不在本仓库**——它们是旧工作空间里的一次性验证脚本，没随工程迁过来，等价断言后来陆续并进了 JVM 单测与 androidTest。读到引用它们的历史段落，按「当时确实跑过」理解，别去找文件。
