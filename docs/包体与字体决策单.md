## 4. 三案（+ 组合案）：体积收益 / 首启体验 / 国内可用性

**「约」的口径**：磁盘字节减去对应条目的压缩后字节。**未重建 APK 实测**——
zip 中央目录会随条目数变化（少 4 个 `.so` + 25 个模型 = 少 29 条），真实值要重打一次包才算数。
下表同时给两份包的读数，**绝对节省字节相同**。

### 案 A · 拆 ABI（只留 arm64-v8a）

| 维度 | 实测 / 事实 |
|---|---|

## 5. 字体案：前提已变，本机零流量可做

### 5.1 历轮登记的前提**不成立**

记忆 `workbuddy-open-items-2026-10-25.md:11` 写的是
「**本机没有可用字体文件、也不便联网拉取**，所以一直没做」。
**本轮实测：本机就有。**

```
C:/Windows/Fonts/NotoSerifSC-VF.ttf    25 129 160 字节（23.97 MB）
```

用 fontTools 4.68.0 读它的 name / fvar / cmap 表（**纯本地，零网络**）：

| 问 | 实测答案 |
|---|---|
| 是不是思源宋体？ | **是**。`Family = Noto Serif SC`，`UniqueID = 2.002;GOOG;NotoSerifSC-ExtraLight;ADOBE`，`Version 2.02`。Noto Serif SC 与 Source Han Serif（思源宋体）是同一套设计的两个名字，Google + Adobe 联合出品 |
| 许可能不能随 APK 分发？ | **能**。name 表 ID 13 原文：`This Font Software is licensed under the SIL Open Font License, Version 1.1`，ID 14 = `http://scripts.sil.org/OFL`。**OFL 1.1 明确允许嵌入与再分发**（需保留许可声明） |
| 有没有 SemiBold？ | **有**。`fvar` 的 `wght` 轴 **min=200 / default=200 / max=900**，7 个命名实例：ExtraLight 200、Light 300、Regular 400、Medium 500、**SemiBold 600**、Bold 700、Black 900 |
| 覆盖够不够？ | cmap **30 928** 个码位，基本汉字 U+4E00–U+9FFF **20 992** 个，扩展 A **6 592** 个，字形总数 **31 058** |
| App 用到的字缺不缺？ | `app/src/main/java` 里用到 **1 266** 个不同汉字，**缺字 0 个** |

**两个必须注意的坑**：

1. **默认实例是 ExtraLight（wght=200），不是 SemiBold。**
   `PostScriptName = NotoSerifSC-ExtraLight`、`TypoSubfamily = ExtraLight`。
   直接把这份 VF 丢进 `res/font/` 引用，拿到的是**极细体**，不是想要的 SemiBold。
   **必须先 pin 到 wght=600 实例化。**
2. **它是变量字体（有 `gvar` / `fvar` / `HVAR` / `STAT` / `avar` 表）。**
   minSdk 24 的 `res/font/` + `Typeface` 路径**不能可靠地选变量轴**
   （`FontVariationSettings` 要 API 26+，且各厂商实现不一）。
   **所以走「实例化成静态 TTF → 子集化」这条路，不要直接塞 VF。**

脚本 `dist/verify/v5.9.5/i7/t20_font_subset.py`，三步：

```
① instancer.instantiateVariableFont(font, {'wght': 600}, updateFontNames=True)
   → 静态 SemiBold，pin 掉轴后 gvar/fvar/HVAR/STAT/avar 全部消失
② subset.Subsetter().populate(text=<字符集>) → subset(font)
   layout_features=['*']、name_IDs=['*']、notdef_outline=True、recommended_glyphs=True
③ 量磁盘字节 + 用 zipfile ZIP_DEFLATED(compresslevel=9) 量压缩后字节
```

**产物只写进 `dist/verify/v5.9.5/i7/font-probe/`（仓库外）。
没有往 `app/src/main/res/font/` 或 `assets/` 放任何东西**——那属实现，等裁决。

### 5.4 三档实测体积（**不是估计值**）

| 档 | 字符集 | 字符数 | 磁盘字节 | MB | zip DEFLATED 后 | 压缩率 | 耗时 |
|---|---|---|---|---|---|---|---|
| **甲 全量** | 不子集，保留全部 30 928 码位 | 30 928 | **14 852 068** | **14.16** | **8 611 497** | 58.0% | 27.7 s（实例化） |
| **乙 GB2312** | GB2312 汉字 6 763 + ASCII + 常用中文标点 | **6 943** | **3 082 156** | **2.94** | **1 855 384** | 60.2% | 0.9 s |
| **丙 只 UI 字面量** | `app/src/main/java` 里出现过的字符 | **1 421** | **602 772** | **0.57** | **366 731** | 60.8% | 0.5 s |

第 ① 步顺带省了一大截：**原 VF 25 129 160 B → 静态 SemiBold 14 852 068 B，省 10 277 092 B**
（pin 掉 wght 轴后 `gvar` 那张逐字形变体表整个消失）。

**三档的取舍（这是真 tradeoff，不是「越小越好」）**：

- **丙档不可交付**。小书房显示的是**用户自己录入的书名与作者**，那是任意汉字，
  不在 UI 字面量集合里。丙档只用来给出**体积下限**，选它会让书名出豆腐块。
- **乙档有覆盖率上限**：GB2312 的 6 763 字只占字体基本汉字区 20 992 字的 **32.2%**。
  常用字够了，但**生僻人名/书名会缺**（例如「龘」「彧」「甯」这类）。
  对一个书架 App 来说这个风险**真实存在**，不是理论风险。
- **甲档零缺字**，代价是 14.16 MB（压缩后 8.61 MB）——**比整个案 A 省下来的 9.58 MB 还大**。
  也就是说：**选甲档字体，会把拆 ABI 的收益全部吃掉还倒亏。**

**还有第四档可选，但需要用户给字符表**：**《通用规范汉字表》8 105 字**
（覆盖 99.99% 的现代出版物用字，含大量人名/地名生僻字）。
本机没有这份表，**按流量约束本轮不下载**。用户若手上有（或允许一次性拉取），
乙档的脚本换个 `text` 参数就能量出第四档，**预计落在乙与甲之间**——
但这是**预计，不是实测**，不许当数字引用。

### 5.5 流量成本（回答 T20 步骤 ③）

| 项 | 成本 |
|---|---|
| **下载字体** | **0 字节**。本机 `C:/Windows/Fonts/NotoSerifSC-VF.ttf` 已存在，全程本地读取 |
| **子集化计算** | **0 字节**。fontTools 4.68.0 本机已装，纯 CPU |

| **用户侧 APK 增量** | 甲 +8.61 MB / 乙 +1.86 MB / 丙 +0.37 MB（**按 DEFLATED 口径**，见 §5.6 的口径警告） |
| 若将来改第四档 | 需要《通用规范汉字表》字符表，**那才可能产生流量**，届时先问用户 |

### 5.6 一个**本轮无法实测**的量，必须标出来

**`.ttf` 放进 APK 后到底压不压缩，现在量不出来。**

- `app/build.gradle` **没有** `aaptOptions` / `noCompress` 覆盖 → 走 AAPT 默认。
- 现有 APK 里 **`.ttf` / `.otf` / `.ttc` 条目数 = 0**，`res/font/` 目录也不存在
  → **没有样本可以反推 AAPT 对字体的默认行为**。

所以 §5.4 给了**两个边界**：

| 若 AAPT 对 `.ttf`… | 甲档净增 | 乙档净增 | 丙档净增 |
|---|---|---|---|
| **STORED**（不压缩，同 `.so`） | +14 852 068 B（14.16 MB） | +3 082 156 B（2.94 MB） | +602 772 B（0.57 MB） |
| **DEFLATED**（压缩） | +8 611 497 B（8.21 MB） | +1 855 384 B（1.77 MB） | +366 731 B（0.35 MB） |

**真实值必须等用户批准、字体进包重打一次才能定。** 复测命令：

```bash
python -X utf8 -c "
import zipfile
z = zipfile.ZipFile('dist/XiaoShuFang-v5.9.6.apk')
for i in z.infolist():
    if i.filename.startswith('res/font/'):
        print(i.filename, i.file_size, i.compress_size,
              'STORED' if i.compress_type == 0 else 'DEFLATED')
"
```

**不许把 §5.4 的任一边界当成实测净增引用。**
